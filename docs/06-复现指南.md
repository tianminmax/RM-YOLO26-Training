## 二、目录摆放

脚本用 `Path(__file__).parent` 定位根目录，因此需要把 `code/` 里的脚本放在**作业根目录**（与 `codebase/`、`data/`、`datasets/`、`runs/` 同级）：

```
assignment4/                     ← 作业根目录
├── codebase/ultralytics-YOLO26/ ← 作业下发的源码（含 yolo26n.pt）
├── data/
│   ├── labeled/{images,labels}/ ← 1511 张已标注
│   └── unlabeled/images/        ← 302 张未标注
├── code/                        ← 复制本仓库的 code/ 到这里
├── configs/                     ← 复制 configs/data.yaml（按本机改 path）
├── datasets/                    ← prepare_data.py 生成
└── runs/                        ← 训练与评估输出
```

```bash
# 从仓库复制脚本到作业根目录
cp -r RM-YOLO26-Training/code        assignment4/code
cp -r RM-YOLO26-Training/configs     assignment4/configs
```

**环境**：Python 3.11 + torch 2.7.1+cu128 + ultralytics 8.4.7（使用本地 CodeBase）。完整版本记录见 [`../results/environment.txt`](../results/environment.txt)。

```bash
conda activate ai-env
python -c "import torch; print(torch.cuda.is_available())"     # 期望 True
```

## 四、为什么数据本身没有放进仓库

数据集共约 215 MB（已标注 180 MB + 未标注 36 MB），而 GitHub 仓库有单文件 100 MB、仓库 1 GB 的软限制，把原始图像直接提交会让仓库变得臃肿且难以维护。当前方案是：

| 方案 | 是否采用 | 说明 |
|---|---|---|
| **Release 附件**（已采用） | ✅ | 数据集打包为 `rm-dataset-1511labeled-302unlabeled.zip`（206.4 MiB），挂在 `dataset-v1` 标签下，下载与校验见 1.1 |
| 划分清单 + 数据集统计 | ✅ | `results/split/*.txt`、`results/dataset_stats.csv`，几 KB，可独立核对划分是否一致 |
| Git LFS 存数据 | ⬜ 备选 | 需要 LFS 配额；适合需要长期在仓库内维护数据版本的情况 |

**发布 Release 的步骤**（若需要重新上传）：

1. GitHub 仓库页 → **Releases** → **Draft a new release**
2. Tag 填 `dataset-v1`，标题填「数据集（1511 张已标注 + 302 张未标注）」
3. 把 `dist/rm-dataset-1511labeled-302unlabeled.zip` 拖进附件区，等待上传完成（约 206 MiB）
4. Publish release，然后按 1.1 的命令下载校验一遍，确认哈希一致

## 五、结果对不上时的排查顺序

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `prepare_data.py` 报"缺少标签" | 数据包解压不完整 | 重新解压，确认 `data/labeled/images` 与 `labels` 数量都是 1511 |
| 划分结果与 `results/split/*.txt` 不一致 | 图片文件集合不同（例如多了缓存文件） | `diff` 两份清单，找出差异文件 |
| 前 10 轮 mAP50 明显低于 0.8 | 标签未被正确读取 / 类别数不匹配 | 跑 `check_det_dataset`，确认 `nc=1`、类别名为 `robot` |
| 训练中途报显存不足 | 显存小于 8G | 降 `--batch`（960 用 4、1280 用 2），或先降 `--imgsz` 跑通流程 |
| 单轮耗时差异很大 | 硬件不同 / 显卡功耗被限制 | 对比 `nvidia-smi -q -d POWER`；功耗限制只影响速度，不影响精度 |
| 指标有极小幅浮动（±0.002 级别） | 不同 GPU 与 cuDNN 算法选择差异 | 属正常范围；本仓库已在同机同配置下验证到"前 30 轮逐点一致" |
| 训练把整机拖死 | `workers` 过大 + 无 swap | 见 [`03-常见问题与排错.md`](03-常见问题与排错.md) A1 |
