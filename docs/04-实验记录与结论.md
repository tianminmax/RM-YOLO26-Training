## 二、逐实验记录

### 实验 1　baseline_n_640（作为基准）

目的：得到一个不做任何调参的参照点。

关键过程（val 集）：

| epoch | 1 | 10 | 25 | 50 | 100 | 146（最佳） | 196（早停） |
|---|---|---|---|---|---|---|---|
| mAP50 | 0.086 | 0.868 | 0.905 | 0.924 | 0.930 | **0.937** | 0.926 |
| mAP50-95 | 0.042 | 0.531 | 0.584 | 0.609 | 0.622 | **0.636** | 0.618 |
| train cls_loss | 4.417 | 1.148 | 0.812 | 0.675 | 0.544 | 0.478 | 0.414 |
| val cls_loss | 4.137 | 0.877 | 0.773 | 0.723 | 0.704 | 0.681 | 0.741 |

结论：

1. **前 10 轮 mAP50 冲到 0.868** —— 迁移学习红利直接可见。
2. 第 50 轮后 mAP50 饱和，但 mAP50-95 仍在缓慢上升 → 瓶颈转为定位精度。
3. 第 146 轮后训练 loss 继续降、验证 loss 回升 = 过拟合，早停在 196 轮触发，`best.pt` 锁定在 146 轮。

### 实验 2　exp_imgsz960（被中断的一组，仅作过程记录）

目的：验证"提高分辨率解决定位精度"的假设。

这一组在训练到第 39 轮时因调整显卡功耗中断，重启续训时被静默覆盖成 `imgsz=640`（详见 `03-常见问题` C1），因此第 40~150 轮不可用于对比。有效部分为前 39 轮，最优出现在第 35 轮（val mAP50 0.9452 / mAP50-95 0.6578），已优于 baseline 的第 146 轮结果——**说明方向正确，但该组曲线不能作为结论依据**，故用 v2 干净重跑。

### 实验 3　exp_imgsz960_v2（最终模型）

唯一变量：`imgsz` 640 → 960（batch 由 8 降到 4 是显存所迫，不算独立变量）。

| 项目 | 值 |
|---|---|
| 最佳 epoch | 135（val mAP50 0.9529 / mAP50-95 0.6729） |
| 总耗时 | 3293 秒（约 55 分钟，约 22 秒/轮） |
| test mAP50 / mAP75 / mAP50-95 | **0.9594 / 0.8202 / 0.6684** |
| test Precision / Recall | 0.9518 / 0.9146 |
| 推理速度 | 3.2 ms/张（imgsz=960，FP16） |

相对 baseline 的提升：

| 指标 | 提升幅度 | 相对 |
|---|---|---|
| mAP50 | +0.0201 | +2.1% |
| **mAP75** | **+0.0488** | **+6.3%** |
| mAP50-95 | +0.0344 | +5.4% |
| Precision | +0.0185 | — |
| Recall | +0.0233 | — |

**核心结论：提升幅度随 IoU 阈值升高而放大**（2.1% → 6.3% → 5.4%）。这直接印证了"模型本来就能找到目标，提高分辨率解决的是框得准不准"，收益集中在高 IoU 区间。同时 Precision 与 Recall 同升，说明不是用误检换召回。

### 实验 4　exp_imgsz1280（主动放弃）

理论上是 960 的自然延伸（像素量再增 1.78 倍），预期还能涨 0.01~0.02 mAP50-95。放弃原因是性价比：8G 显存下 batch 只能降到 2，实测单轮 49 秒、150 轮需约 2 小时，且 batch 过小会降低梯度稳定性。在时间受限的情况下，把这段时间用于整理实验记录更有价值。**该风险已记录：更大输入尺寸与更大模型（yolo26s/m）的上限本次未验证。**

## 三、分辨率消融

| imgsz | mAP50 | mAP75 | mAP50-95 | 相对 mAP50-95 |
|---|---|---|---|---|
| 640 | 0.9393 | 0.7714 | 0.6340 | 基准 |
| 960 | 0.9594 | 0.8202 | 0.6684 | +5.4% |

趋势清晰：**分辨率是本次唯一带来实质提升的变量**。其中 mAP75 的变化幅度最大，说明它最能反映定位质量的改善。

## 四、误差分析（test split）

混淆矩阵（conf=0.25、IoU=0.45 口径）：

| | 真实是 robot | 真实是背景 |
|---|---|---|
| 预测 robot | 963 | 76（误检） |
| 预测背景 | 73（漏检） | — |

1036 个目标中漏检 73 个（7.0%）、误检 76 个，误差分散在多种场景，未出现某一类场景的系统性失效。

**典型失败模式**：抽查 `1035.jpg`（拆解状态的机器人零件堆，被人体遮挡、对比度低）发现，模型在 conf=0.406 时其实已经检出，但预测框把上方的背包与器材一并框入，与标注框 IoU 仅 0.529——在 mAP50 上算命中、在高 IoU 阈值上丢分。

![典型困难样本](../figures/01-典型困难样本.jpg)

改进方向：补充遮挡与杂物密集场景的标注数据；在标注规范中统一"目标与相邻物体粘连时的边界界定"。

## 五、未标注数据预标注评估

用最终模型对 302 张未标注数据做预标注（imgsz=960、conf=0.25），统计如下（完成 300 张）：

| 指标 | 未标注数据（模型预标注） | 已标注数据（人工） |
|---|---|---|
| 平均框数/图 | **4.50** | 4.54 |
| 最高置信度分位 | 25% 0.90 / 中位 0.92 / 75% 0.94 | — |
| 零检出图片 | 4 张 | — |
| 场景分布 | HUD 风格（>6 框）97 张 / 实拍风格（1-3 框）160 张 | 同分布 |

结论：

1. **框密度与人工标注几乎一致**，说明模型对这批数据的理解是稳定的，没有出现"遇到没见过的数据就乱框"。
2. 4 张零检出样本经人工检查后确认：1 张为真实背景（人群照），其余为极端特写（机器人占满画面、无法界定边界）或暗光遮挡的边界样本，不构成错误。
3. 主要差异在于模型对小地图区域也给出预测，而原标注规范未统一该区域——这部分需要人工裁决。

因此该方案质量可用，可直接进入"人工核对后并入训练"阶段，训练集预计可扩充约 29%。

## 六、复现说明

```bash
python code/prepare_data.py
python code/train.py --name baseline_n_640 --epochs 200 --imgsz 640 --batch 8 --workers 2 --device 0
python code/train.py --name exp_imgsz960_v2 --epochs 150 --imgsz 960 --batch 4 --workers 2 --device 0
python code/eval.py --weights runs/exp_imgsz960_v2/weights/best.pt --split test --imgsz 960 --batch 4
python code/analyze_errors.py --weights runs/exp_imgsz960_v2/weights/best.pt --split test --imgsz 960
```

每个实验的完整配置见 `results/<实验名>/args.yaml`，逐轮曲线见 `results/<实验名>/results.csv`。
