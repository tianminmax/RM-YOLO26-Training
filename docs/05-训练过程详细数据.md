# 训练过程详细数据

本文件汇总三个实验的完整训练过程。逐轮原始数据（496 行）见 [`../results/all_epochs.csv`](../results/all_epochs.csv)，每个实验的原始文件见 `../results/<实验名>/results.csv` 与 `args.yaml`。

说明：`mAP75` 只在最终 test 集评估时计算，训练过程中 ultralytics 每轮记录的是 `mAP50` 与 `mAP50-95`。

| 配置项 | baseline_n_640 | exp_imgsz960 | exp_imgsz960_v2 |

| epochs（设定） | 200 | 150 | 150 |

| 优化器 | auto | auto | auto |
| AMP | True | True | True |

| 早停 patience | 50 | 50 | 50 |

| mosaic | 1.0 | 1.0 | 1.0 |
| 随机种子 | 0 | 0 | 0 |

※ 实验 2 在第 39 轮因调整显卡功耗中断，重启后用 `resume` 续训时，启动脚本把默认的 `imgsz=640`、`batch=8` 传了进去，覆盖了断点里原本的 960/4（事故详情见 `03-常见问题与排错` C1）。因此该实验目录里的 `args.yaml` 记录的是**续训后**的配置，而第 1~39 轮实际是在 960 下训练的。

除该事故外，三组实验的差异只有输入尺寸（batch 由显存上限决定），其余配置完全一致。

## 三、训练开销与资源

| 实验 | imgsz | batch | 单轮耗时 | 总轮数 | 总耗时 |
|---|---|---|---|---|---|
| baseline_n_640 | 640 | 8 | 11.0 s | 196 | 36 min |
| exp_imgsz960 | 960 → 640 ※ | 4 → 8 ※ | 960 阶段 23 s / 640 阶段 11.5 s | 150 | 23 min |
| exp_imgsz960_v2 | 960 | 4 | 22.0 s | 150 | 55 min |

※ 见上文的续训事故说明。可见同样在 960 下训练，两次运行的单轮耗时基本一致（23 s 与 22 s），说明测速结果稳定。

- 显存上限决定 batch：8G 卡上 `imgsz=640` 可用 `batch=8`，`imgsz=960` 用 `batch=4`，`imgsz=1280` 只能 `batch=2`（实测单轮约 49 秒）。
- 训练时 AMP（FP16）开启，显存占用约为 FP32 的一半；这是能在 8G 卡上跑 960 的前提之一。
- 训练期间需同时监控内存：`workers=2`、限制 `OMP_NUM_THREADS=4` 后系统保持稳定。
